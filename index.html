        Security Headers Reference

        Key HTTP response headers that harden any web application against common attacks

        Reference
        Content-Security-Policy Critical

        Controls which resources (scripts, styles, images) can load on the page. Mitigates XSS and data injection attacks.

        Content-Security-Policy: default-src 'self'; script-src 'self'

        ThreatLens sets: default-src 'self'; style-src 'self' 'unsafe-inline'

        Strict-Transport-Security High

        Forces browsers to use HTTPS for a set period — prevents SSL-stripping / downgrade attacks.

        Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
        X-Frame-Options High

        Prevents the page from being embedded in <iframe> — blocks clickjacking attacks.

        X-Frame-Options: DENY
        X-Content-Type-Options Medium

        Prevents browsers from MIME-type sniffing — stops content injection via crafted file uploads.

        X-Content-Type-Options: nosniff
        Referrer-Policy Medium

        Controls how much referrer information is included with requests — limits information leakage to third-party sites.

        Referrer-Policy: strict-origin-when-cross-origin
        Permissions-Policy Medium

        Disables browser APIs (camera, microphone, geolocation) the site doesn't need — reduces API abuse attack surface.

        Permissions-Policy: camera=(), microphone=(), geolocation=()

            Common Authentication Attacks

            Know your adversary — these are the most frequent methods attackers use to compromise accounts

            01 Critical

            Phishing / Credential Harvesting

            Fake login pages mimic legitimate sites to steal usernames and passwords. URL analysis (this tool!) is your first line of defense.

            Use a password manager (auto-fills only real domains) Enable phishing-resistant MFA (FIDO2)
            02 High

            Credential Stuffing

            Attackers take leaked username/password pairs from one breach and automatically try them across hundreds of other services.

            Unique password per service Enable login anomaly alerts
            03 High

            SIM-Swap Attack

            Attacker convinces your carrier to transfer your number to their SIM, intercepting all SMS-based 2FA codes in real time.

            Switch from SMS 2FA to TOTP app Add carrier account PIN
            04 Medium

            MFA Fatigue / Push Bombing

            Attackers who already have your password send dozens of push MFA notifications hoping you'll approve one out of frustration.

            Enable number matching in your MFA app Report unexpected pushes immediately
            05 Medium

            Brute Force / Dictionary Attack

            Automated tools try millions of common passwords or words until one matches — especially effective against short or simple passwords.

            Use 16+ character passphrases Enable account lockout policies
            06 Medium

            Session Hijacking

            An attacker steals your active session cookie — often via XSS, public Wi-Fi sniffing, or malware — and impersonates you without needing your password.

            Always use HTTPS (check padlock) Log out on shared devices

            Built for Security Awareness

            Every design decision prioritises safety, transparency, and user education.

            No URL Fetching

            The engine never visits, fetches, or resolves submitted URLs. Analysis is purely string-based, eliminating SSRF risk entirely.

            Explainable Scoring

            Each of 17 rules carries a documented weight. Every triggered rule shows a plain-English explanation so you can learn, not just click.

            Zero Data Storage

            No URL, no IP address, no session data is stored. The analysis runs entirely in memory and is discarded immediately.

            HTTPS Caveat Aware

            ThreatLens explicitly tells you HTTPS doesn't equal safe. Phishing sites routinely obtain valid TLS certificates.

            Rate-Limited API

            Flask-Limiter restricts requests per IP. Security headers (CSP, X-Frame-Options, nosniff) are applied to every response.

            Fully Responsive

            Mobile-first CSS scales from 320 px to wide monitors. Keyboard navigation, visible focus rings, and ARIA labels throughout.

            Privacy & Limitations

            ThreatLens is an educational heuristic tool, not a definitive threat oracle.

            What ThreatLens Does

            • Parses URL structure with stdlib only — no network calls
            • Evaluates 17 independent string-based heuristic rules
            • Returns an explainable, weighted 0–100 risk score
            • Strips credential userinfo before display
            • Communicates clearly that HTTPS ≠ safe

            What ThreatLens Does NOT Do

            • Visit, fetch, or resolve submitted URLs
            • Consult threat databases or blocklists
            • Store submitted URLs or user data
            • Guarantee a URL is malicious or safe
            • Replace professional security tooling
